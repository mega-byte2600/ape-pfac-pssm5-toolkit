Standalone contribution

This is a method others can apply to their own research topics.

The surveillance system is a repeatable method for students, researchers, analysts, PFAC members, patients, care partners, and health system teams who need to monitor literature, organize sources, and translate evidence into action.

The model works for PFACs and PSSM 5, but it can also be adapted to other public health, clinical quality, patient safety, health services research, policy, or implementation science topics.

System architecture

Search strategy to surveillance to catalog to action.

1. Define lanes

Research questions

Create topic lanes before searching so alerts are meaningful. Example lanes: PFAC governance, patient experience and safety, HAI/MRSA patient engagement, co-production, and implementation.

2. Build searches

PubMed/MyNCBI

Use Boolean logic, MeSH terms, title/abstract terms, and saved searches. Turn high-value searches into recurring MyNCBI email alerts.

3. Route alerts

Outlook folders

Create rules that move PubMed and NCBI alert emails into dedicated research folders by topic lane, date, or project.

4. Catalog sources

Zotero collections

Save accepted sources into named collections so the bibliography, annotated bibliography, and source map stay organized.

5. Collaborate

Notion workspace

Use a controlled collaboration layer for source suggestions, benchmark examples, reviewer notes, and toolkit improvement ideas.

6. Translate

Evidence matrix

Move the best sources into the evidence-to-action matrix so literature becomes operational guidance, not a passive reading list.

Operating model

Weekly review keeps the evidence current and usable.

The weekly cycle is simple: review alerts, remove duplicates, screen abstracts, save accepted sources, tag by topic lane, update the evidence catalog, promote high-value sources into the matrix, document what changed in the toolkit, and route collaboration inputs for review.

Did this source change the evidence base?
Does it support a patient benefit or reveal patient risk?
Does it create a PFAC question or leadership action?
Does it belong in the bibliography, matrix, toolkit, or collaboration backlog?

Example SQL

Starter schema for a reusable evidence catalog.

create table search_queries (
  query_id text primary key,
  topic_lane text not null,
  database_name text not null,
  query_text text not null,
  date_created date not null,
  alert_enabled boolean default true,
  notes text
);

create table sources (
  source_id text primary key,
  date_captured date not null,
  source_type text not null,
  topic_lane text not null,
  title text not null,
  authors text,
  journal_or_publisher text,
  publication_year int,
  pmid text,
  doi text,
  url text,
  zotero_key text,
  abstract_notes text,
  relevance_summary text,
  evidence_use text,
  patient_benefit text,
  patient_risk_if_ignored text,
  pfac_action text,
  leadership_action text,
  metric_connection text,
  competency_connection text,
  status text default 'Captured'
);

create table surveillance_alerts (
  alert_id text primary key,
  query_id text references search_queries(query_id),
  received_at timestamp not null,
  email_folder text,
  source_id text references sources(source_id),
  triage_status text default 'To Screen'
);

create table collaboration_items (
  item_id text primary key,
  submitted_at timestamp not null,
  submitter_role text,
  item_type text not null,
  title text not null,
  url text,
  topic_lane text,
  notes text,
  review_status text default 'Submitted',
  reviewer_notes text
);

create table evidence_tags (
  tag_id text primary key,
  tag_name text not null unique,
  tag_type text not null
);

create table source_tags (
  source_id text references sources(source_id),
  tag_id text references evidence_tags(tag_id),
  primary key (source_id, tag_id)
);

create table evidence_actions (
  action_id text primary key,
  source_id text references sources(source_id),
  action_type text not null,
  action_summary text not null,
  owner_role text,
  due_date date,
  status text default 'Proposed'
);

Replication guide

How another researcher can use this method.

  1. Choose a topic

    Define a practical question that requires ongoing evidence surveillance.

  2. Create search lanes

    Separate the topic into 3 to 5 focused lanes rather than one oversized search.

  3. Save PubMed searches

    Use MyNCBI alerts to receive new results on a regular cadence.

  4. Route emails

    Use Outlook rules to move alerts into triage folders automatically.

  5. Catalog accepted sources

    Save sources in Zotero and record key metadata in the SQL catalog.

  6. Translate evidence

    Promote high-value sources into an evidence matrix and update the product, paper, or implementation plan.
